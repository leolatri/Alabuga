## 🚀 Быстрый старт
### 1) Собрать и запустить всё
docker compose up -d --build

### 2) Посмотреть статус контейнеров
docker compose ps

### 3) Логи (по желанию)
docker compose logs -f db
docker compose logs -f api
docker compose logs -f web


Остановить всё:

docker compose down


Полный сброс с удалением данных БД (осторожно!):

docker compose down -v

🌐 Что открывать в браузере

Фронт: http://localhost:8080

API (Swagger): http://localhost:8000/docs

Через Nginx в фронте проксируется путь /api/* → в бекенд api:8000, поэтому можно сразу дёргать JSON:

http://localhost:8080/api/store

http://localhost:8080/api/missions

http://localhost:8080/api/profile/22222222-2222-2222-2222-222222222222
 (тестовый пользователь из сидов)

🗄️ Миграции/SQL

Применить все .sql из папки init в уже работающую БД:

chmod +x scripts/apply_sql.sh
./scripts/apply_sql.sh db ./init


Пересобрать только API (если код поменялся):

docker compose up -d --build api

✅ Проверки (EDU-контур)

Во всех запросах ниже нужен заголовок X-User-Id: <int> — это ID пользователя из edu.users. В сидере есть пользователь 1.

### Профиль (PersonDTO)
curl -H "X-User-Id: 1" http://localhost:8000/edu/profile

### Лидерборд (LeaderDTO[])
curl -H "X-User-Id: 1" http://localhost:8000/edu/leaderboard

### Мои артефакты (ArtifactDTO[])
curl -H "X-User-Id: 1" http://localhost:8000/edu/artifacts

### Все ветки (BranchDTO[])
curl -H "X-User-Id: 1" http://localhost:8000/edu/branches

### Конкретная ветка (BranchDTO)
curl -H "X-User-Id: 1" http://localhost:8000/edu/branches/1

### Список миссий ветки (ContentDTO[])
curl -H "X-User-Id: 1" http://localhost:8000/edu/branches/1/missionsList

### Миссия по ID (ContentDTO)
curl -H "X-User-Id: 1" http://localhost:8000/edu/mission/2

🧩 Полезно знать

.env
В корне лежит файл .env (пример):

POSTGRES_DB=gameapp
POSTGRES_USER=appuser
POSTGRES_PASSWORD=secret


Фронт → API
Фронт ходит к бекенду по относительному пути /api/... (настройка уже в Docker/Nginx).

Картинки
В «старом» домене (роли/миссии/магазин) изображения приходят как Base64; в EDU — как строки/URL из БД.

DEV режим (если фронт отдельно)
Если запускаешь CRA на http://localhost:3000 вне Docker, включи CORS в app/main.py (есть закомментированный блок) или используй proxy в фронте.

🛠️ Эндпоинты (кратко)
EDU (/edu), заголовок X-User-Id: <int>

GET /edu/profile → профиль (PersonDTO)

PUT /edu/profile → обновить профиль (PersonDTO)

GET /edu/leaderboard → лидерборд (LeaderDTO[])

GET /edu/artifacts → артефакты пользователя (ArtifactDTO[])

GET /edu/branches → все ветки (BranchDTO[])

GET /edu/branches/{id} → ветка (BranchDTO)

GET /edu/branches/{id}/missionsList → миссии ветки (ContentDTO[])

GET /edu/mission/{id} → миссия (ContentDTO)

«Старый» домен (без префикса)

GET /profile/{user_uuid} → профиль с артефактами и топом

GET /store → товары магазина

GET /missions → опубликованные миссии

(HR только, заголовок X-User-Id: <UUID HR>)

POST /missions → создать миссию

PUT /missions → редактировать миссию

POST /store (multipart) → создать товар

PUT /store/{id} (multipart) → редактировать товар

🧯 Частые проблемы

Порт занят → поменяй мэппинг портов в docker-compose.yml (например, 8081:80, 8001:8000).

Фронт не видит API → открой http://localhost:8080/api/missions. Если JSON есть — прокси ОК; проверь, что фронт вызывает '/api/...'.

Сиды не применились → база уже инициализирована. Прогоните ./scripts/apply_sql.sh db ./init или выполните полный сброс docker compose down -v (удалит данные).

SQL-ошибки вида sql в начале файла → уберите случайные маркеры тройных кавычек ``` и слово sql из первых строк .sql файлов.

## Реализованные User Cases для пользователя

### UC-01: Отслеживание прогресса развития компетенций

#### Как пользователь, я хочу видеть свой текущий статус и прогресс, чтобы понимать свое положение в карьерной траектории.

1) Сотрудник заходит в раздел "Профиль"

2) Система отображает:

- Аватар и имя

- Текущий ранг: "Пилот-кандидат"

- Progress Bar: "66%: 300XP"

- Мана: 180 

- Место в общем рейтинге

### UC-02: Просмотр коллекции артефактов

#### Как пользователь, я хочу видеть свои достижения, чтобы гордиться прогрессом и мотивироваться на новые свершения.

1) В профиле пользователь опускается ниже по странице и видит полученные "Артефакты"

- Изображение артефакта

- Название артефакта

- Описание артфеакта

### UC-03: Просмотр таблицы лидеров

#### Как пользователь, я хочу видеть прогресс других пользователей, чтобы мотивировться и следить за общим прогресс

В профиле пользователь опускается ниже по странице и видит "Доска рейтинга". В ней отображаются 

1) Место пользователя

2) Имя пользователя

3) Количество набранных очков

### UC-04: Просмотр доступных веток задач

#### Как пользователь, я хочу видеть все возможные пути развития, чтобы выбирать наиболее подходящие для моих целей.

1) Пользователь заходит в раздел "Задачи"

2) Система отображает доступные ветки задач в процессе и вкладку с ветками "Завершенные". В ветках отображаются:

- Количество опыта за ветку

- Количество маны за ветку

- Название ветки

- Описание ветки

- Тип ветки

- Кнопка "Приступить"

3) Пользователь переходит в ветку, отображается список миссий:

- Количеством опыта за миссию

- Названием миссии

- Краткое описание миссии

- Тип миссии

- Кнопка "Выполнить"

4) Пользователь переходит в карточку миссии, где отображаются: 

- Полное описание миссии

- Артефакт получаемый за миссию

### UC-05: Покупка мерча за ману

#### Как пользователь, я хочу обменивать игровую валюту на реальные товары, чтобы чувствовать осязаемую выгоду от своей активности.

1) Пользователь заходит в раздел "Магазин"

2) Система отображет список товаров, где видно

- Название товара 
- Цена товара
- Иконка товара
- Кнопка "+" для добавления в корзину

3) Пользователь нажимает на "+" "Футболка Спектр" за 100 маны

4) Пользователь переходит в корзину, видит выбранные товары и подтверждает покупку кнопкой "Оплатить"

## Реализованные User Cases для сотрудника HR

### UC-01: Создание новой задачи и ветки

#### Как HR, я хочу быстро добавлять новые ветки и задачи, чтобы поддерживать актуальность платформы.

1) HR заходит в раздел веток

2) Отображается список веток

3) HR нажимает на кнопку создать ветку

4) Открывается форма создания ветки, где можно заполнить поля:

- Название ветки

- Тип

- Введите краткрое описание

5) Доступна кнопка "Добавить миссию", при нажатии открывается форма создания миссии с полями

- Название миссии

- Тип миссии

- Введите краткое описание

- Полное описание

- Количество маны

- Количество опыта

6) При сохранениии миссия привяжется к данной ветке

7) Пользователь возвращается в раздел веток, нажимает на иконку "Карандаша" и редактирует существующую ветку в открывшейся форме 

### UC-02: Аналитика активности пользователей

#### Как HR, я хочу видеть статистику по платформе, чтобы оценивать эффективность и вовлеченность.

1) HR заходит в раздел "Пользователи"

2) Система показывает дашборд:
 
- ID пользователя

- ФИО пользователя

- Опыт пользователя

3) HR вводит ФИО для поиска конкретного пользователя и отследить его прогресс
